이 워크플로우는 작성된 블로그 포스트의 기술적 정확성과 스타일 가이드를 검토하며, 특히 **프론트엔드**, **백엔드**, **인프라** 레이어별로 전문적인 리뷰를 수행합니다. 또한 코드 스타일, 보안 취약점, 유지보수성을 집중적으로 분석하여 개선 방향을 제시합니다.

# 리뷰 절차

### 1. 기본 코드 품질 및 보안 검토 (Style & Security)
- **코드 스타일 준수**: 각 언어별(Java, JS, YAML 등) 표준 스타일 가이드를 준수했는지 확인합니다.
- **보안 취약점 및 민감 정보 검토**: 
  - **하드코딩된 민감 정보**: API 키, 비밀번호, 인증 토큰, 비밀 값(Secret) 등이 코드 내에 직접 입력되어 있는지 철저히 검사합니다.
  - **취약점 분석**: SQL Injection, XSS 등 보안상 위험 요소가 있는지 검토합니다.

### 2. 레이어별 전문 리뷰 (Frontend, Backend, Infrastructure)
- **프론트엔드**: UI 구성의 적절성, 프레임워크 권장 패턴, 성능 최적화 및 웹 접근성 확인.
- **백엔드**: 비즈니스 로직의 정확성, API 설계 원칙, 데이터베이스 쿼리 효율성 및 테스트 코드 검증.
- **인프라**: 클라우드 설정(AWS, Docker)의 재현 가능성, 확장성 및 CI/CD 자동화 무결성 검토.

### 3. 유지보수 및 잠재적 문제 분석 (Maintenance & Risk Analysis)
- **더 나은 코드 제안**: 가독성, 재사용성, 확장성 측면에서 더 나은 설계나 구현 방식을 제안합니다.
- **잠재적 결함 안내**: 미래에 성능 저하, 동시성 이슈 등으로 인해 문제가 생길 수 있는 코드를 분석하여 안내합니다.

### 4. 로컬 렌더링 확인 (Common)
// turbo
- `pnpm l` 명령어를 실행하여 빌드 오류가 없는지 확인합니다.
- 브라우저에서 실제 레이아웃과 수식, 코드 하이라이팅이 깨지지 않는지 확인합니다.

### 5. 결과 보고 및 커밋 제안 (Reporting & Suggestion)
- 모든 검토 항목의 결과를 요약하여 보고합니다.
- **중요**: 에이전트는 직접 커밋을 수행하지 않습니다. 대신 `bloger` 스킬의 규칙(`title: [포스트 제목]`)에 따른 커밋 메시지와 이를 실행할 수 있는 `git commit` 명령어를 사용자에게 제안합니다. 최종 커밋은 사용자가 직접 수행합니다.

# 체크리스트 (Summary)
- [ ] **API 키, 비밀번호 등 민감한 정보가 하드코딩되어 있지 않은가?**
- [ ] 보안 취약점(SQL Injection, XSS 등)이 없는가?
- [ ] 유지보수가 용이한 구조인가?
- [ ] 향후 발생 가능한 성능 이슈나 환경적 제약 사항이 분석되었는가?
- [ ] Frontmatter(`title`, `date`, `tags`) 형식이 올바른가?
- [ ] `h1` 태그가 하나만 존재하며 계층 구조가 정상인가?
- [ ] 모든 코드 블록에 언어 명시가 되어 있는가?
- [ ] 에이전트가 커밋 메시지와 명령어를 적절히 제안하였는가?
