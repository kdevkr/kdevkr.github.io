이 워크플로우는 프로젝트 내에 하드코딩된 API 키, 비밀번호, 인증 토큰 등의 민감 정보 노출을 방지하고, 잠재적인 보안 취약점을 식별하여 안전한 코드 베이스를 유지하는 것을 목적으로 합니다.

# 보안 검사 절차

### 1. 자격 증명 및 민감 정보 노출 스캔
- **환경 변수 파일 검사**: `.env`, `.env.local`, `config.json`, `settings.yaml` 등 설정 파일 내에 실제 비밀 값(Secret, Password, Token)이 하드코딩되어 있는지 확인합니다.
- **코드 내 리터럴 스캔**: 소스 코드(`src/`, `lib/`, `tests/` 등) 내에 `API_KEY`, `PASSWORD`, `SECRET`, `TOKEN`, `JWT`, `AUTH`, `PRIVATE`, `ACCESS_KEY` 등의 키워드와 함께 할당된 문자열 리터럴을 `grep_search` 등을 사용하여 집중적으로 스캔합니다.
- **파일 패턴 확인**: `.pem`, `.key`, `.p12`, `.pfx`, `.json` (GCP Key 등) 등 민감한 인증서나 키 파일이 프로젝트 내에 의도치 않게 포함되어 있는지 확인합니다.

### 2. `.gitignore` 및 설정 검토
- **제외 설정 확인**: `.env`, `node_modules`, `dist`, `build`, `idea`, `.vscode`, `.gemini` 등 민감하거나 불필요한 파일이 `.gitignore`에 제대로 등록되어 있는지 확인합니다.
- **공개 저장소 노출 위험**: 공용 저장소(GitHub 등)에 업로드되면 안 되는 민감 파일이 추적(tracked)되고 있지는 않은지 검토합니다.

### 3. 잠재적 코드 취약점 분석
- **입력 유효성 검사**: 사용자 입력이 직접 쿼리나 HTML에 삽입되어 Injection(SQL, XSS) 위험이 있는지 분석합니다.
- **의존성 보안**: // turbo
  - `npm audit` 또는 `pnpm audit`을 실행하여 알려진 취약점이 있는 라이브러리를 사용 중인지 확인합니다.

### 4. 보고 및 개선 제안
- 발견된 모든 보안 위험 요소를 중요도(**Critical**, **High**, **Medium**, **Low**)에 따라 분류하여 보고합니다.
- **조치 권고**: 
  - 하드코딩된 키는 즉시 교체(**Revoke & Rotate**)하고 환경 변수로 분리할 것을 권고합니다.
  - `.gitignore` 누락 시 추가 규칙을 제안합니다.
  - 취약한 의존성은 버전 업데이트를 제안합니다.

# 보안 체크리스트 (Summary)
- [ ] `.env` 파일에 실제 비밀 값이 포함되어 있고, 이 파일이 `.gitignore`에 등록되어 있는가?
- [ ] 코드 내에 `const API_KEY = "..."`와 같은 하드코딩된 자격 증명이 없는가?
- [ ] `.pem`, `.key`와 같은 인증 파일이 프로젝트 루트나 소스 디렉토리에 포함되어 있지 않은가?
- [ ] 사용자 입력을 처리하는 곳에서 적절한 이스케이프나 파라미터화된 쿼리를 사용하는가?
- [ ] `npm audit` 결과 해결이 필요한 고위험(High) 이상의 취약점이 없는가?
- [ ] 클라우드 설정 파일(AWS/GCP/Azure configs)이 포함되어 있지 않은가?
- [ ] 에이전트에 의해 보안 위험 요소가 우선순위별로 분류되어 보고되었는가?
