# 명령어 사용 규칙

토큰 최소화를 최우선으로 합니다. 결과를 받기 전에 "이 출력이 정말 필요한가, 더 좁힐 수 있는가"를 먼저 판단하세요.

## 전용 도구 우선

Bash 대신 전용 도구를 사용합니다.

| 목적 | 사용 | 금지 |
|---|---|---|
| 파일 검색 | `Glob` | `find`, `ls -R` |
| 내용 검색 | `Grep` | `grep`, `rg` |
| 파일 읽기 | `Read` | `cat`, `head`, `tail` |
| 파일 수정 | `Edit` / `Write` | `sed`, `awk`, `echo >` |

이유: 전용 도구는 페이징·라인넘버·필터링이 내장되어 동일 작업에서 토큰을 60~90% 절감합니다.

## 출력 범위를 먼저 좁히기

- `git log`는 항상 `-n <개수>` 또는 `--oneline`을 붙입니다. 무제한 로그 금지.
- `git diff`는 파일 경로를 지정합니다. 전체 diff는 마지막 수단.
- `Read`는 큰 파일에서 `offset`/`limit`로 필요한 구간만 읽습니다.
- `Grep`은 `output_mode: "files_with_matches"`를 우선 시도하고, 내용이 필요할 때만 `"content"`로 재호출합니다.

## 실패 처리

- 모든 명령어가 실패하면 같은 명령을 반복하지 말고, 원인을 추정해 사용자에게 확인 후 다시 시도합니다.
- 권한·인증 오류는 즉시 보고합니다 (예: `gh auth status` 확인).

## 병렬 실행

서로 의존성이 없는 명령은 한 번의 응답에서 동시에 호출합니다. 순차 호출은 응답 라운드를 늘려 시스템 프롬프트가 반복 청구됩니다.

## RTK 프록시

이 저장소는 RTK(Rust Token Killer)가 활성화되어 있습니다. 일반 명령은 훅이 자동으로 `rtk <cmd>`로 변환하므로 직접 `rtk`를 붙이지 않습니다. 단, `rtk gain`·`rtk discover` 같은 메타 명령은 그대로 사용합니다.
