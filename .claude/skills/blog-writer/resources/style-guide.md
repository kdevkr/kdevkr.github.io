# 기술 블로그 스타일 가이드

기술 블로그(`kdevkr.github.io`) 포스트 작성 규격입니다.

## 1. Frontmatter 규격

```yaml
---
title: 포스트 제목
date: YYYY-MM-DD'T'HH:00+09:00
description: 한 줄 요약 (목록·OG 메타용, 40~80자 권장)
tags:
  - 키워드1
  - 키워드2
---
```
# [포스트 제목]

- **빈 글로 시작**: 새 포스트는 Frontmatter와 단일 `# 포스트 제목`만 포함된 빈 파일로 먼저 생성합니다.
- **문서 제목 (H1)**: Frontmatter 바로 아래에 `# 포스트 제목`을 반드시 포함합니다.
- **date**: 정시 단위의 `YYYY-MM-DD'T'HH:00+09:00` 형식(분 단위 `00` 고정)을 지킵니다.
- **description**: 글 목록(`/posts`)과 SNS 공유 미리보기에 노출되는 한 줄 요약입니다. 제목과 겹치지 않게 핵심 맥락을 40~80자로 적습니다.
- **tags**: 관련 키워드 2~4개를 YAML 배열로 작성합니다.

## 2. 문서 구조 및 헤더
- **H1 (`#`)**: 페이지 제목으로만 쓰며 문서당 **단 하나**만 둡니다.
- **계층 구조**: 큰 주제는 `##`, 하위 주제는 `###`을 사용합니다.
- **도입부**: 문서 제목 바로 아래에 글의 목적과 요약을 1~2문장으로 적습니다.
- **구분선 (`---`) 금지**: `##`, `###` 헤더 위에는 `---`를 두지 않습니다. 테마가 자동으로 렌더링하는 하단 구분선과 겹칩니다.
- **요약/마치며 섹션 금지**: 하단에 `마치며`, `요약`, `정리` 같은 상투적인 결론 섹션(H2)을 두지 않고 마지막 본문 섹션에서 자연스럽게 마칩니다.
- **참고 자료 섹션**: 출처는 본문 인라인 링크(`[텍스트](URL)`)를 기본으로 합니다. 본문에 녹이기 어려운 링크만 글 끝 `## 참고 자료` 섹션에 `- [원문 제목](URL)` 목록으로 모읍니다(목록 내 `—` 사용 금지).

## 3. 이미지 및 미디어
- **저장 경로**: `public/images/posts/[포스트파일명]/` 아래에 `001.png`, `002.png`처럼 세 자리 숫자로 저장합니다.
- **참조 경로**: `public`을 뺀 `/images/posts/[포스트파일명]/[번호].png` 형식으로 참조합니다(`file:///` 경로 금지).
- **도식화 (`mermaid` 금지)**: `mermaid` 코드 블록 대신 SVG나 이미지 파일로 생성해 연결합니다.

## 4. 코드 블록
- **언어 명시**: 모든 코드 블록에 언어(`ts`, `go`, `yaml`, `bash` 등)를 명시합니다.
- **타이틀 추가**: 파일명·제목 표시는 ```` ```언어 [타이틀] ```` 형식을 씁니다(예: ```` ```json [settings.json] ````).
- **설명**: 코드 블록 위나 아래에 핵심 설명을 덧붙입니다.

## 5. 텍스트 서식
- **강조**: 핵심 키워드에만 절제하여 `**굵게**` 또는 `==강조==`를 사용합니다.
- **렌더링 주의**: 닫는 `**`나 `==` 바로 뒤에 한글 조사·특수문자가 붙으면 렌더링이 깨질 수 있으므로 한 칸 띄어 씁니다(예: `**강조** 를 위해`).
